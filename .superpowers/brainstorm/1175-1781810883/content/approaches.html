Language Filter UX — 3 Approaches

Which direction feels right for fixing the include/exclude confusion?

A

Unified List with Role Toggle

One searchable list. Each language gets a 3-state toggle: Off → Include (green) → Exclude (red). Clear visual distinction, no separate sections. Badges below are color-coded green/red. Search bar at top for quick filtering.

Pros

  • Single section — no confusion about which list is which
  • Clear visual hierarchy: green = include, red = exclude
  • Search solves the 100+ language scrolling problem

Cons

  • Redesigns the current section layout
  • Toggle per language is slightly more clicks for bulk adds
B

Keep Sections, Add Color + Search

Keep the two separate sections but: color-code badges (green for include, red for exclude), add a search bar inside each dropdown, and show a toast warning when adding to one side removes from the other.

Pros

  • Minimal structural change — low risk
  • Color distinction makes include vs exclude obvious
  • Search helps find languages fast

Cons

  • Still two sections — takes more vertical space
  • Mutual exclusion still silent (just warned via toast)
C

Chip Grid with Color States

All available languages shown as clickable badge chips in a scrollable grid. Click to cycle: Default → Include (green) → Exclude (red) → Default. Search bar at top to filter the grid. No dropdown, no "Add" button — everything visible at a glance.

Pros

  • Everything visible at once — fastest interaction
  • Color states make include/exclude instantly clear
  • Search + visual = best of both worlds

Cons

  • 100+ chips can look dense (mitigated by search)
  • Biggest UI change from current pattern
